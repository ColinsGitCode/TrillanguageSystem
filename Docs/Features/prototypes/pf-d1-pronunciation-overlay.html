S1 · READING SURFACE

默认状态不把每个汉字做成按钮。轻微的点划线只表示“这里有按需读音”，不改变文字选择。

Product contract

阅读优先

活动 DOM 只保存用户真正阅读、选择和复制的字符。读音不修改正文。

  • 正文可读PASS
  • Ruby 标签0
  • 悬停写入 KGNO

S2 · HOVER / FOCUS

快速查看整词读音

250ms 延迟 · 只读 · Escape 或离开关闭

Tooltip 只展示“整词 + 读音 + 类型”，没有按钮、输入框或业务动作。

No side effects

悬停不是查词

只有用户主动点击 Popover 中的“查知识点”才会进入 KG 查询链路。

  • 按钮无
  • KG event无
  • 学习记录无

动作各归原域

Popover 只是协调器。TTS、KG、学习计划和生成卡仍调用各自已有服务。

  • 调度状态不由注音拥有
  • 关闭后焦点恢复

Hit-area rule

一层主 Token

正文不嵌套多个可点击 span，避免一个词语出现多个互相抢焦点的命中区域。

S5 · INFLECTION

活用关系

词形信息来自确定性分析，读音仍可单独修正

Evidence

分析不是裁决

Kuromoji 输出是确定性证据；人工修正会进入 append-only correction event，并在重分析后保留。

纯正文、复制和选择仍然可用；只有读音相关动作被限制。

S8 · SELECTION FIRST

拖动时不弹浮层

指针移动超过阈值后，文字选择优先

选区工具条已出现：标红 · 复制 · 查知识点 · 生成卡片。Tooltip/Popover 自动关闭。

Arbitration

选区优先级最高

  • Selection 非空阻止 Popover
  • 右键重新读取 Range
  • 旧 hasSelection不依赖

S9 · DOUBLE CLICK

双击选择整词

accepted token 可精确预览，unresolved 不越权扩大

来月の 勤務表、もう掲示板に貼ってあったよ。

双击“勤務表”得到一个完整 selection，显示现有工具条；不会把“の”或标点一起选中。

Selection contract

整词来自已确认边界

双击不是靠连续汉字正则猜词，而是读取 accepted pronunciation token 的 surface 范围。

S10 · KEYBOARD

注音导航模式

显式进入后才启用 roving tabindex

来月勤務表掲示板食べました

方向键在当前句 token 间移动；Enter/Space 打开 Popover；Escape 回到正文，不关闭 CardModal。

Accessibility

不制造几十个 Tab 停靠点

默认正文不把每个词放进 Tab 序列。进入注音导航后，只有当前 token 可聚焦。
