S1 · DEFAULT

没有来源时明确说“待确认”

不猜测 · 不留空 · 不伪装成已知
待确认

このインターフェースは分かりやすい。

这个界面很好懂。

インターフェースいんたーふぇーす外语来源 待确认

系统没有该词的已确认外语来源。

这是当前线上的真实状态：实测 26 个片假名词中有 22 个落在这里。

Contract

空状态必须诚实

没有来源就显示“待确认”，不填英文猜测、不隐藏该行。用户可以随时自己补。

  • 猜测来源禁止
  • 人工补录入口常驻

Contract

权威也要能纠错

“来源不对”对 curated 同样可用——否则优先级链最上层的“人工修正”是空的（§3.1）。

  • 标签措辞不含 AI
  • 纠错入口有

未经确认 · 不可伪装成权威

确认每天早上的日程。

schedule（英语）

实测同一批卡片连跑三次，候选覆盖率在 64%–76% 之间摆动 —— 所以默认 pending 不是保守，是必需。

Contract

三个出口，缺一不可

接受、修改后接受、拒绝。只给“接受”会诱导用户点确认，等于把 LLM 输出洗成事实。

  • 视觉区分虚线 + 琥珀
  • 置信度参与排序否

S4 · ACCEPTED

Audit

裁决是事实，不是覆盖

接受写入裁决记录，不删除原候选，可回滚。

  • 改动正文否
  • 改动 content_hash否

S5 · HUMAN CORRECTION

修改后接受 = 人工修正

优先级最高，压过精选词典
人工修正

このソフトは使いやすい。

这个软件很好用。

ソフトそふとAI 候选：soft

AI 给的是 soft；此处实际是 software 的截短形。

保存后该词的来源由人工拥有，之后任何 AI 候选或词典条目都不会覆盖它。

Priority

人工在最上层

这正是 S2 的“来源不对”最终落地的地方：人工修正写入 accepted 记录并高于 curated。

  • 改词典文件否
  • 可回滚是

S6 · REJECTED

拒绝后不再反复打扰

回到“待确认”，但记住这个候选已被否掉
待确认

そのシーンが印象に残った。

那个场景让人印象深刻。

シーンしーん外语来源 待确认

已拒绝一个 AI 候选（scene · 2026-08-10）。

同一正文版本下不会再次提示相同候选。

拒绝不等于“这个词没有外语来源”，只是这一次的候选不对。区别要在文案上说清楚。

Contract

否决要有记忆

拒绝写入裁决事实；重复提取遇到同一候选不再打扰，但换了候选仍可提示。

ja-pronunciation-v2.json 永不原地改写；覆盖关系在数据里表达，不在文件里表达。

S8 · MIXED

同一张卡上四种状态共存

用户一眼要能分辨哪个可信

データをリフレッシュして、プロジェクトのフィードバックを確認する。

刷新数据，确认项目的反馈。

  • 精选 データ → data可信
  • 已确认 リフレッシュ → refresh可信
  • AI 候选 プロジェクト → project待裁决
  • 待确认 フィードバック—
四种状态有各自的下划线样式与配色，不依赖单一颜色区分（色觉友好）。

Legibility

可信度必须外显

混合状态是常态，不是边界情况：提取覆盖不到 100%，且人工确认永远滞后于提取。

S9 · EXTRACTION RUNNING

第二段提取尚未完成

卡片已可正常使用
提取中

このアカウントでログインする。

用这个账号登录。

アカウントあかうんと外语来源 提取中

正在后台提取外来语来源…

卡片正文、朗读、标记和学习不受影响。

主卡生成与元数据提取解耦：提取还没回来时，卡片已经完全可用。

Decoupling

不阻塞阅读

提取是第二次 best-effort 调用，实测成功延迟中位约 1.5 秒。

  • 阻塞卡片否
  • 手动补录仍可用

S10 · EXTRACTION FAILED

“提取失败”不能显示成“没有外来语”

这是 JLM-D0 §7 的核心要求
提取失败

セキュリティの設定を見直す。

重新检查安全设置。

セキュリティせきゅりてぃ提取未完成

后台提取超时，本卡尚未产出候选。

这不代表该词没有外语来源。

实测出现过 2/8 次 120 秒超时。若没有任务记录，这 25% 会被误读成“这些卡没有外来语”。

Failure semantics

三种“没有”要分开

  • 没有外来语正常空
  • 提取未完成可重试
  • 候选被校验拒绝见 S11

S11 · SERVER REJECTED

模型给了，但服务端定位不到

不落库、不展示，但要可见原因
待确认

カレンダーに予定を入れる。

把安排写进日历。

カレンダーかれんだー外语来源 待确认

本次提取产出的候选未通过服务端校验。

拒绝原因
surface-not-found（模型给的词形不在正文中）
服务端拒绝的候选一律不入库、不显示。这里只暴露“为什么没有结果”，不暴露被拒的内容本身。

Validation

幻觉不进产品

P0 实测共 12 种拒绝原因；成功运行中服务端零拒绝，说明校验层可靠。

  • 被拒候选入库否
  • 原因可见是

Integrity

  • 跨版本复用禁止
  • 历史正文改写从不
