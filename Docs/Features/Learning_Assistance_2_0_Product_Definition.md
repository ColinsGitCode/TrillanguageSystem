## 0. 文档定位与权威边界

本文是学习辅助 2.0 的 LA-D0 产品定义，负责回答：用户为什么使用、每天完成什么任务、系统如何解释安排、v1 做到什么程度，以及 LA-D1 原型必须表现哪些状态。

权威关系固定为：

1. 产品依赖方向、知识图谱后置和退役边界以上位设计基线为准；
2. 本文是学习者任务、产品术语、核心流程和 v1 默认策略的权威来源；
3. LA-D1 只把本文转成桌面端交互，不得新增产品能力或修改学习规则；
4. LA-D2 决定实体、事件、状态、算法参数、时区和删除策略，但不得改变本文的用户承诺；
5. DP0-DP7 只提供合格卡集合和审计证据，不直接创建学习对象；
6. 标签与未来知识图谱只提供可选分组/排序信号，不拥有计划、队列、评分或复习状态。

## 1. 产品结论

学习辅助 2.0 v1 是一个面向单个学习者的**桌面端主动回忆工作台**，不是卡片生成页的附属统计条，也不是知识图谱浏览器。

核心承诺只有一个：

> 用户打开系统后，可以在两次主要点击内知道今天学什么、为什么学，并完成一段可中断、可恢复、可解释的学习会话。

产品闭环固定为：

```text
选择学习范围与每日目标
  -> 系统生成可解释的今日队列
  -> 用户主动回忆并揭示答案
  -> 用户给出四档反馈
  -> 系统保存不可变学习证据并更新下次安排
  -> 展示今日进度、积压和下一步
```

Cards Factory 继续负责生产、查看和管理卡片；学习辅助 2.0 负责消费合格卡片并形成学习闭环。两者通过 `generation_id` 和内容版本衔接，不共享页面职责。

## 2. 目标用户与使用情境

### 2.1 目标用户

- 单个本地用户；
- 中文母语，主要学习英语和日语；
- 已有持续增长的三语卡、日语语法卡和场景表达卡；
- 使用桌面浏览器，学习时需要阅读、发音播放和主动回忆；
- 需要系统减少“今天选什么”的决策负担，但不接受不可解释的黑箱安排。

### 2.2 主要使用情境

1. **每日开始**：打开系统，看到到期量、新卡配额、预计行动数和积压情况；
2. **短时学习**：用 5-15 分钟完成一小段队列，可以随时停止；
3. **集中复习**：处理到期、逾期或连续失败的项目；
4. **定向学习**：临时缩小到英语、日语语法、某日期或某标签范围；
5. **恢复会话**：关闭页面或服务重启后，从下一个未完成项目继续；
6. **理解安排**：随时知道当前项目来自“逾期复习”“今日到期”“困难项重现”还是“今日新卡”。

### 2.3 非目标用户

v1 不面向多用户班级、教师布置作业、社交竞争、移动端碎片化学习或跨设备同步。上述需求不得提前污染本地单用户模型。

## 3. 用户任务

| ID | 用户任务 | 完成标准 |
|---|---|---|
| LA-J1 | 建立学习范围 | 能选择合格卡范围、学习语言方向和每日目标，并看懂预计规模 |
| LA-J2 | 开始今日学习 | 有队列时两次主要点击内进入第一项；无队列时看到明确原因和可执行动作 |
| LA-J3 | 主动回忆 | 先看到提示面，再主动揭示答案；答案未揭示前不能误评分 |
| LA-J4 | 使用音频辅助 | 揭示答案后可播放英文/日文音频进行核对与跟读；TTS 暂时不可用不阻断已有内容复习 |
| LA-J5 | 提交学习反馈 | 用四档反馈表达回忆结果，提交后立即进入下一项并显示调度解释 |
| LA-J6 | 中断与恢复 | 已提交结果不丢失，未提交项不产生复习事件，恢复时从下一未完成项继续 |
| LA-J7 | 理解进度 | 能区分今日完成、剩余、逾期积压、新卡和暂停项 |
| LA-J8 | 控制负担 | 能暂停计划、跳过当前项或降低新卡量，不被积压强制进入无限会话 |

## 4. 核心产品流程

### 4.1 首次进入

1. 系统检测是否已有活动计划；
2. 没有计划时进入简洁的计划设置，而不是空白仪表盘；
3. 默认范围是 DP7 合格卡，排除 quarantined、unresolved 和已确认测试卡；
4. 用户确认学习语言、范围、每日行动目标和新卡上限；
5. 系统预览“可学习单元数、预计首日新卡、当前到期数”；
6. 保存后进入今日队列。

### 4.2 日常进入

1. 默认进入“今日学习”；
2. 顶部显示今日完成、剩余、逾期积压和新卡配额；
3. 主操作是“继续学习”或“开始学习”；
4. 次要操作允许查看队列组成和调整今日新卡上限；
5. 不要求先进入 Cards Factory 挑卡。

### 4.3 单项复习

```text
提示面（不显示或播放目标语言答案）
  -> 用户主动回忆
  -> 揭示答案
  -> 查看目标语言、中文解释、例句并按需播放音频
  -> 选择 重来 / 困难 / 记住 / 简单
  -> 保存事件和调度结果
  -> 下一项
```

评分只能由当前复习会话拥有。Cards Factory 卡片弹窗和嵌入式内容不得出现第二组会写复习事件的评分按钮。

### 4.4 会话结束

- 正常完成：显示完成量、各评分分布、困难项数量和下次到期概览；
- 提前结束：保存已提交结果，未提交项回到可选队列，不计失败；
- 队列为空：区分“今日已完成”“范围内没有合格卡”“计划已暂停”“仅有未决数据”；
- 有积压但达到今日目标：明确显示仍有多少到期项，并允许继续，不用惩罚性文案。

## 5. v1 产品决策

### 5.1 学习单元粒度

| 卡型 | v1 决策 | 原因 | 展示上下文 |
|---|---|---|---|
| 三语卡 | 每张卡拆成 English 与 Japanese 两个学习单元 | 一次评分无法准确代表两种目标语言；拆分后反馈更有意义 | 可展开查看完整三语卡，中文区作为共享解释 |
| 日语语法卡 | 一个语法点对应一个学习单元 | 三条例句共同证明同一语法点，拆开会丢失规则上下文 | 提示面显示语法点；答案面显示说明、三条例句与日语音频 |
| 场景表达卡 | 每个 `### 01-12` 表达对应一个学习单元 | 整卡认知负担过大；按表达拆分能形成可评分动作 | 保留场景标题、角色和原始场景；可查看同卡其它表达 |

不采用以下方案：

- 所有卡都按整卡复习：三语卡反馈含糊，场景卡过重；
- 场景卡拆成英文/日文共 24 项：首版队列膨胀，用户难以保持场景整体语义；
- 每条例句单独成为学习项：会把例证误当成独立知识点。

LA-D2 需要定义稳定 locator、内容 hash 变化和拆分结果的版本策略，但不能改变上述产品粒度，除非先修订 LA-D0。

### 5.2 学习目标

v1 的主目标是**行动数**，不是连续天数、积分或单纯分钟数。

- 默认每日目标：20 个已提交学习行动；
- 默认新单元上限：5 个；
- 到期复习优先于新单元；
- 用户可以把新单元上限设为 0，只清到期项；
- 时间只做预计和结果指标，不作为强制完成条件；
- 达到 20 个行动后允许继续处理到期积压，但不自动追加新单元。

选择行动数的原因：评分事件是稳定、可审计的完成单位；分钟数受阅读和中断影响大；“卡片数”在拆分后语义不一致。

当前 DP7 合格范围按 §5.1 粒度展开后的规模为：

| 来源 | 合格卡 | 学习单元 |
|---|---:|---:|
| 三语卡 | 435 | 870（English + Japanese） |
| 日语语法卡 | 183 | 183 |
| 场景表达卡 | 3 | 36（每卡 12 项） |
| `whole-card-only` | 1 | 1 |
| **合计** | **622** | **1090** |

按每日 5 个新单元且每天都用满配额，首次引入全部学习单元的理论下限为 218 个学习日；按每日 10 个为 109 个学习日。由于到期复习优先、可能存在非学习日，真实周期会更长。首次计划设置和后续范围调整必须预览：当前范围的卡片数、展开后的学习单元数、按当前新单元上限计算的理论最短天数。用户可以先选择较小范围或提高新单元上限，不应在不知道量级的情况下默认接收全部 1090 项。

### 5.3 计划模型

v1 只允许**一个活动计划**：

- 一个活动计划包含范围、学习语言、每日目标、新单元上限和暂停状态；
- 用户可以编辑范围，不需要创建多个互相竞争的计划；
- 改范围不删除历史学习证据；
- 不在当前范围的学习单元保留状态，但不进入今日队列；
- 未来多计划必须重新评审队列冲突、目标归属和重复统计。

### 5.4 今日队列优先级

产品优先级固定为：

1. 逾期且最近失败；
2. 其它逾期；
3. 今日到期且最近失败；
4. 其它今日到期；
5. 困难项重现；
6. 今日新单元。

同一优先级内由可解释的稳定规则排序，不依赖知识图谱。标签和未来语义 provider 可以提供次级分组/排序分数，但 provider 失败时必须得到相同的基础队列集合。

v1 不随机打乱整个队列。为避免连续同类疲劳，可以在不破坏到期优先级的前提下交错 English、Japanese、Grammar 和 Scenario。

### 5.5 四档反馈

| 反馈 | 用户语义 | 产品结果 |
|---|---|---|
| 重来 | 没想起来或答案错误 | 记为失败，在当前会话或短期内再次出现 |
| 困难 | 想起来但明显吃力、依赖提示 | 记为成功但低置信度，下次间隔较短 |
| 记住 | 正常回忆且答案基本正确 | 记为标准成功，按常规间隔安排 |
| 简单 | 几乎立即、稳定且无提示回忆 | 记为高置信度成功，可使用更长间隔 |

按钮只表达用户感受，不在文案中显示算法术语。具体间隔和调度公式属于 LA-D2；系统必须在提交后用自然语言解释“为什么下次是这个时间”。

### 5.6 学习状态

用户需要看见的状态只保留：

- 新内容；
- 学习中；
- 今日到期；
- 已逾期；
- 困难；
- 已掌握；
- 已暂停；
- 内容已归档。

“已掌握”不表示永不复习，而是达到 LA-D2 定义的稳定条件。内部算法状态不得直接暴露成主导航或大量技术标签。

### 5.7 学习日与中断

- 用户可见学习日按配置时区计算，默认沿用 `Asia/Shanghai`；
- 跨午夜会话中的每个已提交事件按提交时间归属学习日；
- 会话本身可以跨午夜，但午夜后新增队列使用新学习日；
- 浏览器关闭、刷新或服务重启不会重复提交已评分项目；
- 仅揭示答案但未评分，不产生复习事件。

### 5.8 标红与学习调度

- v1 把 Cards Factory 标红视为用户笔记，不自动提高难度、不缩短间隔，也不强制加入队列；
- 复习答案面可以显示已有标红，帮助用户回看个人关注点；
- 标红可作为未来 Heuristic Provider 的可选解释信号，但启用前必须用真实复习数据证明价值；
- 删除或修改标红不重写既有 Review Event。

### 5.9 默认回忆方向

v1 默认采用**生产式主动回忆**，不是目标语言识别：提示面不提前显示或播放目标语言答案；音频位于答案面，用于揭示后的发音核对和跟读。v1 不提供独立听力识别队列，未来若增加听力模式，必须作为新的学习方向单独定义提示、答案和评分语义。

| 学习单元 | 提示面 | 用户回忆目标 | 答案面 |
|---|---|---|---|
| 三语 English | 中文翻译与简短中文释义，不显示英文答案 | 产出自然英文对应表达 | 英文翻译、英文解释、英文例句、例句中文译文和英文音频 |
| 三语 Japanese | 中文翻译与简短中文释义，不显示日文答案 | 产出自然日文对应表达 | 日文翻译、日文解释、日文例句、例句中文译文和日文音频 |
| 日语语法 | 语法形式与一个简短中文使用情境 | 回忆核心含义、使用条件，并尝试给出一个日语例句 | 中文语法说明、核心结构、三条日语例句和日语音频 |
| 场景表达 | 场景标题/角色和当前一条中文表达 | 同时产出自然英文与日文表达 | 英文、日文、使用提示和两种目标语言音频 |

场景表达采用一个组合评分；只要 English 或 Japanese 任一方向明显失败，就按较弱方向选择反馈。该取舍与“不拆成 24 项”一致，LA-D1 不得自行改成单语言场景单元。

计划语言筛选必须继承这一粒度：场景表达只有在 English 与 Japanese **同时启用**时才进入计划范围；缺任一方向时整组场景单元排除，并在范围预览中说明原因。系统不得为了满足单语言筛选而把场景表达临时拆成单语言项目。

## 6. 信息架构边界

LA-D1 必须在现有 React Router 桌面侧栏中新增独立学习区域，建议工作名称：

| 区域 | 职责 |
|---|---|
| Cards Factory | 生成、OCR、卡片库、历史、删除、标红和 CONTENT/INTEL |
| 今日学习 | 今日队列概览、开始/继续、积压和完成状态 |
| 学习计划 | 活动计划范围、目标、新卡上限、暂停/恢复 |
| 复习会话 | 单项主动回忆、揭示答案、音频和四档反馈 |
| 学习记录 | 完成量、评分分布、积压变化和历史趋势；已由 LA-P3 启用 |

LA-D1 可以把“今日学习”和“学习计划”组合成同一路由下的不同视图，但不得把完整复习会话塞回 Cards Factory 首屏。

当前只设计桌面端。已有移动样式不要求删除，但 LA-D1 不提供移动稿，LA-P 阶段不以移动断点作为验收门禁。

## 7. 关键页面状态

### 7.1 今日学习

- 首次使用，无活动计划；
- 有计划且有到期项；
- 有计划，仅有新单元；
- 达到今日目标但仍有积压；
- 今日全部完成；
- 计划暂停；
- 合格卡为 0；
- 队列加载失败但 Cards Factory 可正常使用。

### 7.2 计划设置

- 默认合格范围；
- 按卡型、日期、学习语言和 active 标签筛选；
- 范围为空；
- 修改范围会移出部分学习单元；
- 新卡上限为 0；
- 暂停与恢复确认。

### 7.3 复习会话

- 提示面；
- 答案面；
- 音频可用/不可用；
- 评分提交中；
- 提交失败可重试且不重复记事件；
- 当前内容已删除或更新；
- 提前结束；
- 队列完成。

## 8. 可解释性要求

每个队列项至少显示一个主原因：

- 逾期复习；
- 今日到期；
- 困难项重现；
- 今日新内容；
- 手动加入本次会话。

可选次级解释包括：最近评分、上次学习时间、所属卡型/语言、计划范围和启发式分组。解释不得泄露 prompt、模型私有推理或不可验证的“AI 认为重要”。

评分提交后的解释至少包含：

- 本次反馈；
- 状态是否改变；
- 下次复习的自然日或相对时间；
- 影响安排的公开因素，例如“首次失败”“连续记住”“内容已暂停”。

## 9. 异常与数据变化策略

### 9.1 卡片内容更新

- 学习记录不能因 Markdown 更新而消失；
- UI 需要提示“内容已更新”；
- 是否重置或降低稳定度由 LA-D2 决定；
- 用户必须能查看当前内容，历史事件只保留当时的内容版本标识，不复制整份 Markdown。

### 9.2 卡片删除

- 已产生学习记录的项目不物理丢失历史；
- 删除来源卡后，学习单元进入“内容已归档”，不再排队；
- 尚未学习且来源被删除的项目可以在投影清理中移除；
- 具体 FK 和 tombstone 策略留给 LA-D2。

### 9.3 未决或隔离数据

- DP7 `quarantined` 与 `unresolved` 不生成可学习单元；
- `qa:test-artifact` 永久排除；
- `qa:test-artifact-candidate` 在人工结论前排除；
- `whole-card-only` 是[数据整备计划](Learning_Assistance_2_0_Data_Preparation_Plan.md) DP7 的资格状态：内容经人工决定可整体学习，但结构不支持可靠自动拆分；此类项只能形成一个完整卡片学习单元。

### 9.4 服务降级

- 标签/provider 不可用：使用卡型、日期和复习实证生成基础队列；
- TTS 不可用：显示文字内容并明确音频不可用，不阻断评分；
- DeepSeek 不可用：已有卡片仍可学习；
- 数据库写入失败：不得伪装评分成功，保留当前项供重试。

## 10. 产品术语

| 中文术语 | 英文标识 | 定义 |
|---|---|---|
| 学习单元 | Study Item | 可独立进入队列、揭示答案和评分的稳定对象 |
| 学习计划 | Study Plan | 当前学习范围和每日约束；v1 只有一个活动计划 |
| 今日队列 | Daily Queue | 某学习日根据计划、到期状态和上限生成的可解释项目集合 |
| 学习会话 | Study Session | 用户连续处理一组队列项的交互过程，不是完成事实的唯一来源 |
| 复习事件 | Review Event | 每次成功提交反馈后产生的不可变学习证据 |
| 调度状态 | Schedule State | 由历史事件计算出的当前到期时间、稳定度和状态投影 |
| 新单元 | New Item | 从未产生有效复习事件的学习单元 |
| 学习中 | In Progress | 已有有效复习事件，但尚未达到稳定掌握条件的学习单元 |
| 到期 | Due | 计划复习时间属于当前学习日且尚未完成 |
| 逾期 | Overdue | 计划复习时间早于当前学习日且尚未完成 |
| 困难项 | Difficult Item | 最近反馈或调度证据表明需要更短间隔的项目 |
| 已掌握 | Mastered | 达到 LA-D2 稳定条件的学习单元；仍可在未来再次到期，不表示永久结束 |
| 暂停 | Suspended | 保留历史与状态，但不进入自动队列 |
| 归档 | Archived | 来源内容已删除或不再可学习，保留历史审计 |

禁止在新实现中复用旧表名来表达这些新术语。

## 11. 成功指标

### 11.1 核心漏斗

1. 有可用队列的学习日；
2. 打开“今日学习”；
3. 开始会话；
4. 提交第一个反馈；
5. 达到今日目标或主动正常结束；
6. 次日/7 日/30 日回访。

### 11.2 产品指标

| 指标 | 定义 | v1 用途 |
|---|---|---|
| 今日学习开始率 | 有队列的学习日中启动会话的比例 | 判断入口和队列是否有用 |
| 会话完成率 | 正常完成或主动结束且至少提交 1 项的会话比例 | 判断流程是否可持续 |
| 今日目标完成率 | 达到每日行动目标的学习日比例 | 判断默认目标是否合理 |
| 到期完成率 | 当日已处理到期项 / 当日可处理到期项 | 判断积压控制能力 |
| 逾期积压 | 学习日结束时仍逾期的项目数 | 判断调度负担 |
| 新单元转化 | 新单元首次进入队列后产生首次反馈的比例 | 判断计划范围质量 |
| 评分分布 | 四档反馈按卡型/语言分布 | 判断粒度与难度是否合理 |
| 重复失败率 | 同一项目连续“重来”的比例 | 发现内容、粒度或前置知识问题 |
| 单项用时 | 从提示面到反馈提交的有效时长 | 识别过重学习单元 |
| 计划跳过率 | 被跳过、暂停或移出范围的比例 | 识别推荐不符合意图 |

### 11.3 初始验证假设

上线后前 14 个实际学习日只建立基线，不用任意 KPI 惩罚用户。首轮产品判断采用：

- 有队列时能在两次主要点击内进入第一项；
- 已提交反馈不丢失、不重复；
- 至少 80% 的开始会话产生有效反馈；
- 到期积压不会因系统自动追加新卡而持续恶化；
- 场景表达单项中位用时显著低于整张场景卡预估；
- 用户能从 UI 直接说出当前项目为何出现。

14 个学习日后根据真实行为重设目标，不在设计阶段伪造留存结论。

## 12. 产品事件语义

本节只定义指标语义，不定义表结构：

| 事件 | 触发时机 | 不应触发 |
|---|---|---|
| `plan_activated` | 首次激活或从暂停恢复活动计划 | 仅预览或取消编辑 |
| `daily_queue_opened` | 用户打开某学习日队列 | 后台预计算 |
| `session_started` | 用户进入第一项提示面 | 只查看今日概览 |
| `answer_revealed` | 用户主动揭示答案 | 自动预加载答案 |
| `review_submitted` | 四档反馈完成持久化 | 点击后写入失败 |
| `item_skipped` | 用户明确跳过当前项 | 提前结束整个会话 |
| `session_ended` | 正常完成或用户主动结束 | 浏览器崩溃且没有恢复结论 |
| `daily_goal_reached` | 当日有效反馈达到行动目标 | 仅到达页面或播放音频 |

Review Event 是学习领域事实；分析事件不得代替 Review Event，也不得反向驱动调度。

### 12.1 LA-P3 产品指标实现说明

LA-P3 先使用已经存在且可审计的领域事实完成产品反馈，不创建第二套 Engagement 事件仓库：

- `review_submitted` 直接使用 append-only Review Event；
- Daily Queue 快照提供当日目标和被分配的到期/新单元；
- session 状态与 Review Event 共同判断会话是否产生有效反馈；
- `learning_day` 是按提交时区写入的事实，历史聚合禁止重新按裸 UTC 切日；
- `/learn/history` 以 7/30/90 天和全部范围展示完成行动、到期积压、评分、响应时间、单元拆分和最近评分；
- 前 14 个实际学习日只显示基线剩余天数，不输出好坏判断。

`item_skipped`、`daily_queue_opened` 等产品事件的语义仍保留，但当前领域模型没有持久化 append-only 产品事件。特别是 skip 在结束会话后恢复为待处理，LA-P3 不从 queue entry 的瞬时状态伪造历史跳过率。是否建立 durable analytics event stream 留给独立后续决策，不属于 LA-P3。

## 13. v1 非目标

- 知识图谱、聚类、同义关系和图可视化；
- 多活动计划和计划间优先级；
- 自动生成课程、考试或作业；
- 积分、等级、排行榜、徽章和惩罚性 streak；
- AI 自动评分用户口语或自由文本；
- 移动端页面、移动端断点和移动端验收；
- 多用户、登录、云同步和权限；
- 从旧 SRS 表迁移状态或复活旧页面；
- 让 LLM 直接决定间隔或队列顺序。

## 14. 风险与取舍

| 风险 | 当前取舍 | 后续验证 |
|---|---|---|
| 三语卡拆成两个单元后数量增大 | 接受数量增长，换取语言方向独立反馈 | 比较 English/Japanese 评分分布和用时 |
| 场景卡 12 项可能造成同卡重复 | 保留场景上下文并做卡型交错，不拆成 24 项 | 观察跳过率、单项用时和连续疲劳 |
| 四档反馈增加选择成本 | 保留信息质量，用清晰语义和快捷键降低成本 | 观察评分停留时间和分布偏斜 |
| 单一计划限制灵活性 | v1 优先避免多队列冲突 | 记录用户是否频繁改范围 |
| 默认 20/5 可能过高或过低 | 作为可编辑默认值，14 个学习日后调整 | 观察目标完成率与积压 |
| 无图谱分组较粗 | 保证稳定降级，先用卡型/日期/标签/实证 | 由真实失败与混淆数据定义 KG-D0 |

## 15. LA-D1 原型输入

LA-D1 必须逐页提供以下桌面端可视化，不得只画理想态：

1. 侧栏和学习区域的信息架构；
2. 首次计划设置；
3. 今日学习默认态；
4. 有逾期积压的今日学习；
5. 今日完成态；
6. 三语 English 学习单元提示面/答案面；
7. 三语 Japanese 学习单元提示面/答案面；
8. 日语语法学习单元；
9. 场景表达学习单元及场景上下文；
10. 四档反馈、提交中、提交失败和调度解释；
11. 提前结束与恢复会话；
12. 卡片更新、归档、TTS 不可用和空范围状态。

LA-D1 的自包含静态原型负责镜像当前桌面侧栏、design tokens、Markdown renderer 输出结构、ruby、音频与标红的视觉和交互契约；它不连接真实 schema，也不得用假 API 或虚构筛选计数掩盖未决领域问题。真实 React Router + Markdown renderer + 音频/标红数据链路已在 LA-P2 浏览器门禁中完成验证，不能由静态镜像替代。

### 15.1 LA-D1 原型记录（2026-07-13，复审修订版已确认）

原型以 12 页交付，存档于 [prototypes/la-d1-prototype.html](prototypes/la-d1-prototype.html)（自包含 HTML + UTF-8 文档头，静态镜像生产 token 值，明暗双主题，真实语料）。**首版曾声明 12/12 完成，经复审撤回**；以下缺口在修订版补齐后，用户已于 2026-07-13 全部确认：

- 补全文档骨架（doctype / html lang / meta charset），静态服务器直接打开无乱码；
- 「评分提交中」（全部禁用防双击）、「提交失败」（评分锁定，仅重试/更改评分）、「主动提前结束」（确认 + 摘要）三个状态独立成帧；
- 「仅有未决数据」从空范围态拆出，独立成态并带处理动作；
- 场景单元在队列中改为 `EN+JA` 双语标识（不得标单语言，粒度契约 §5.1）；
- 三语答案面补目标语言解释行，展示标红只读示例；内容结构为 Markdown renderer 输出的静态镜像，**renderer 实链路已由 LA-P2 浏览器门禁验证**（原型本身仍不连接真实渲染管线）；
- 场景单元固定为 `EN+JA`：只有两个语言方向同时启用时才进入范围，缺任一语言时排除并解释，不允许临时拆成单语言项目；
- 暂停文案收敛为「不进入自动队列」，到期日处理规则显式归 LA-D2（不在 D1 预定调度语义）；
- 计划设置可交互：语言/卡型点选、数值钳制（目标 5-100 / 新卡 0-50）、规模预览实时联动、新卡 0 = 只清到期；日期/标签改为可叠加筛选器入口且不伪造计数；范围变更影响确认、暂停确认对话框补齐；
- 复习会话评分区固定置底、正文独立滚动，低视口（1280×720）无需滚动即可评分；空格揭示与 1-4 评分快捷键真实可用。

原型期间确认的交互级决策，LA-D2 与实现必须继承：

1. **复习会话不是导航目的地**：侧栏为「学习」组（今日学习 / 学习计划 / 学习记录；原型时学习记录为 P3 预留，现已启用）+「生产」组（Cards Factory）；复习会话仅由「开始/继续学习」进入。
2. **新单元与复习同流程**：新卡不设独立学习模式，首次评「重来/困难」属正常路径（v1）。
3. **积压时的新卡降额是建议 + 一键采纳**：系统不得静默修改用户的新单元上限配置。
4. **提交语义三分**：提交中（全禁用）/ 失败待重试（锁定评分，仅重试或显式更改评分）/ 可评分——失败重试不得产生重复事件。
5. **场景语言范围固定双语**：场景表达只在 English 与 Japanese 同时启用时进入计划；语言筛选不得改变场景学习单元粒度。
