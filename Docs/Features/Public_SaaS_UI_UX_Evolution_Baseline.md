# Three LANS 公开 SaaS UI/UX 演进基线

> 状态：Draft / 公开化诊断与实施基线 / PS-P0、PS-G0、PS-P1、复习专注模式、统一 Page Header、知识点恢复入口、首次使用空状态与学习闭环清单、跨域待办中心、统一页面状态、复杂流程离开保护、高成本任务恢复、全局系统信息入口、匿名公开沙箱与 UI-R2 公开质量治理已实施
>
> 日期：2026-07-30
>
> 范围：桌面端产品体验、公开访问边界、流程连续性、状态可信度、可恢复性、可访问性与发布质量
>
> 明确不做：账户中心、团队、角色、邀请、订阅、计费和移动端适配

## 0. 结论

Three LANS 当前已经不是一个简单的本地页面。它已经具备：

- React Router 桌面 App Shell；
- Cards Factory、学习辅助、教材课程和知识点四个产品域；
- 可恢复的复杂工作流、后台任务、人工确认和审计记录；
- 统一设计 token、暗色模式、键盘焦点、Markdown、ruby 和音频能力；
- 真实数据、TTS、DeepSeek、FSRS 和知识图谱的完整业务链路。

下一步不应该再做一次全站换皮。真正需要补的是：

1. 陌生用户第一次进入时，能否快速理解系统；
2. 用户切页、刷新、跨天或后台任务失败后，能否继续原来的工作；
3. 页面显示的数字、状态和下一步，是否始终可信；
4. 匿名公开访问时，是否会泄露或互相修改数据；
5. AI、教材原文、用户确认事实和系统推断，是否清楚区分；
6. 出现限流、离线、服务降级或内部错误时，页面是否仍然可用。

因此下一轮定位为：

> **Public SaaS Readiness：从“功能完整的单机工作台”升级为“陌生用户也能安全理解和完成任务的公开 SaaS 产品”。**

## 1. “公开 SaaS”不等于“所有人共享一个数据库”

### 1.1 当前真实边界

当前 Express 运行时直接挂载生成、学习、教材、知识图谱、注解和文件 API。系统没有账户、租户或访问隔离层，数据主要落在同一份 SQLite 和本地媒体目录。

如果直接把现有端口公开到互联网，会出现三个严重问题：

- 任意访客可以看到同一批教材、卡片、学习记录和知识点；
- 任意访客的生成、评分、删除或发布操作会修改同一份真实数据；
- DeepSeek、TTS 和后台 worker 资源可能被匿名请求耗尽。

这不是 UI 美化可以解决的问题。

### 1.2 本阶段允许的两种运行模式

#### 模式 A：单工作区模式

- 面向系统所有者或可信使用者；
- 完整读写、学习历史和长期数据都保留；
- 可以部署到公网，但必须由网关访问密钥、VPN 或反向代理保护；
- 不增加账户中心、团队和角色管理。

#### 模式 B：公开体验沙箱

- 面向匿名访客；
- 每个浏览器获得独立、可过期的体验空间；
- 默认使用合成教材和演示卡片；
- 写操作只进入该沙箱，超过保留期限自动清理；
- DeepSeek、TTS、文件上传和后台任务设置严格额度；
- 不允许访问所有者的真实 SQLite、教材原文和媒体文件。

### 1.3 明确禁止的模式

不得提供“匿名访客共同读写一个长期数据库”的公开版本。

如果未来希望匿名用户长期保留自己的复习进度，就必须至少引入一种稳定身份。身份可以很轻，但本质上已经超出本阶段“不增加用户管理”的边界。

## 2. 当前 UI 的成熟部分

以下能力应保留，不应重新推翻：

1. 左侧产品域导航和紧凑桌面 Shell；
2. Cards Factory 的三类卡片生产入口；
3. 教材课程的 Stage、Task、Review 和可恢复 operation；
4. 学习辅助的主动回忆、揭示答案、四档评分和 sticky 评分区；
5. 知识点的确定性事实、AI proposal 和人工确认边界；
6. 全站统一语言色、卡型色、状态色和可见焦点；
7. 右上角后台活动入口与跨页面反馈事件；
8. 复杂流程中的保存、冲突、重试、Review Summary 和 Activity Log 原语。

公开化应在这些基础上补齐产品连续性和可信度，而不是再做一套平行组件。

## 3. 核心问题诊断

### 3.1 P0：跨天未完成会话可能被隐藏

当前“今日学习”同时读取今日队列和活动会话，但渲染顺序先处理“今日没有队列”，再处理活动会话。

实际结果可能是：

- 昨天仍有一个未结束会话；
- 今天尚未生成新队列；
- 页面只显示“生成今日队列”；
- 用户看不到“继续昨天的会话”。

这对公开产品很危险，因为用户无法判断数据是否丢失。

目标体验：

- 顶部首先显示“昨日未完成会话”；
- 主动作：“继续昨日学习 1/5”；
- 次动作：“结束旧会话并生成今日队列”；
- 在用户明确处理旧会话前，不静默创建冲突的新会话。

### 3.2 P0：复习页的进度数字语义混合

当前复习页顶部使用每日 action goal 显示 `1 / 20`。但本次实际队列可能只有 5 个项目。

普通用户会把它理解为“当前是 20 道题中的第 1 道”，而不是“今日目标 20 次”。

目标体验：

- `本次进度 1 / 5`
- `今日目标 0 / 20`
- 两种进度使用不同标签和不同进度条；
- “结束本次会话”和“完成今日目标”使用不同文案。

### 3.3 P0：教材确认状态与发布事实可能不一致

真实页面曾出现“Track 已发布、20 条表达可浏览”，同时顶部显示 `0/0 已确认`。

无论原因来自旧 revision、workflow view-model 或前端选择错误，公开产品都不能让两个互相矛盾的状态同时出现。

目标体验：

- Track 顶部状态只读取一个权威 view-model；
- 显示“20/20 已确认 · 已发布”；
- 旧 revision、当前 revision 和发布 revision 明确区分；
- 发现状态矛盾时显示“状态需要刷新”，不展示推测数字。

### 3.4 P0：公开写入没有隔离

当前 API 没有公开访客隔离。所有 UI 改进都必须以第 1 节的运行模式为前提。

目标体验：

- Shell 明确显示“个人工作区”或“体验沙箱”；
- 沙箱显示过期时间和数据保留说明；
- 受限制的操作解释原因，不展示服务器环境变量；
- 所有高成本操作显示剩余额度或冷却时间；
- 沙箱清理前提供明确提示。

### 3.5 P1：后台活动只在当前浏览器会话里可靠（已于 PS-P1 第一批修复）

当前 Shell 的 Activity Drawer 会把活动摘要放入 `sessionStorage`。它适合即时反馈，但不能作为后台 Job 的权威状态。

刷新、重新打开浏览器或换标签后，用户可能看不到仍在运行的服务端任务。

目标体验：

- Activity Center 启动时从服务端读取真实 Job；
- `sessionStorage` 只保存 UI 展开状态，不保存权威业务状态；
- 运行、部分失败、失败和需要人工处理时显示数量；
- 空闲时保持图标模式，异常时显示“失败 2”等文字；
- 每条活动都能返回对应对象和恢复动作。

实施后，`GET /api/activity` 已成为只读聚合入口。它直接读取卡片生成任务、教材
operation、活动学习会话和 KG 增量同步事实，不新增平行活动表。`sessionStorage`
只保留最多 10 秒的即时乐观提示，以及某个服务端来源临时降级时的可用提示，
不再决定刷新后的权威状态。

### 3.6 P1：首次使用缺少产品内引导

当前空状态大多告诉用户“没有数据”，但没有把四个产品域串成一条可理解的学习闭环。

目标体验不是营销落地页，而是直接进入可用工作台并提供轻量引导：

1. 创建或导入学习内容；
2. 检查教材/卡片；
3. 建立学习计划；
4. 完成第一次复习；
5. 查看学习记录和知识点。

引导必须：

- 可以跳过；
- 不遮挡主界面；
- 完成后不反复出现；
- 每一步都跳到真实功能，不播放不可操作的演示。

### 3.7 P1：空状态占用大，但提供的下一步太少

Cards Factory、学习记录和知识点页面在无数据时会留下大面积空白。

目标体验：

- 每个空状态只给一个主动作和最多一个次动作；
- 显示最近对象、示例或待处理项，而不是三块同时空白；
- Cards Factory 提供“创建第一张卡”和“查看最近生成”；
- 学习记录在有活动会话时优先显示“继续学习”；
- 知识点默认显示最近查询和待确认项。

### 3.8 P1：学习答案信息层级不够清楚

长语法卡在揭示答案后会同时显示解释、例句、误用、音频和评分。内容正确，但认知负担较高。

目标体验：

- 第一层：核心答案；
- 第二层：解释与对比例句；
- 第三层：误用、扩展和来源；
- 每个句子只保留一个主要播放入口；
- 可选提供“连续播放”；
- 评分区继续固定，但不与内容操作竞争。

### 3.9 P1：教材发布后仍保留过多生产流程

教材 Workflow 对导入和校对非常重要。但 Track 发布后，用户的主要任务已经从“生产”切换为“学习和查阅”。

目标体验：

- 已发布 Track 默认进入教材浏览；
- 五阶段流程收起成一条“已发布”摘要；
- Manifest intake、hash 和调试信息进入高级工具；
- 当前表达高亮更明显，支持上下方向键切换；
- 官方 Track 音频显示明确播放进度和当前状态；
- 选区工具只在用户完成选择后出现。

教材截图解析仍由 Codex Skill 在应用外完成，页面不增加 OCR 或自动配对入口。

### 3.10 P1：知识点页面初始状态不利于开始任务

当前页面强调三栏结构，但未选择知识点时，匹配、详情和学习动作可能同时为空。

目标体验：

- 初始左栏显示最近查询、待确认或推荐入口；
- 中栏只在选中对象后显示规范形、词形关系和来源证据；
- 右栏容量文案仅在可执行“加入本次学习”时出现；
- “待确认 50”改为“待处理 50”，并提供优先级和原因；
- AI proposal 与确定性事实继续保持视觉分离。

### 3.11 P2：语言和页面标题规则仍不完全统一

当前界面混合中文主任务、英文 eyebrow 和英文产品名。英文不是问题，但需要固定规则。

建议规则：

- 用户任务和状态优先中文；
- `Cards Factory`、Track、EN/JA 等产品名或标准缩写保留；
- 技术日志、revision、provider 进入详情区；
- 页面统一使用“上下文 - 主标题 - 状态 - 一个主动作”的 Header 模式。

### 3.12 P2：领域 CSS 继续增长会造成视觉漂移

当前设计 token 基础良好，但教材、知识点和 Workflow 样式已经承担大量重复布局。

下一步应提取共享原语：

- `PageHeader`
- `ActionableEmptyState`
- `WorkspaceBadge`
- `StatusStrip`
- `EntityRail`
- `DetailPanel`
- `InspectorPanel`
- `RecoveryBanner`

提取目标是减少重复和统一行为，不是为了制造新的抽象层。

## 4. 公开 SaaS 需要新增的横向体验

### 4.1 工作区身份

Shell 固定显示当前模式：

- `个人工作区`
- `体验沙箱 · 23 小时后清理`

用户必须清楚自己正在修改哪一份数据。

### 4.2 全局恢复中心

优先显示以下未完成工作：

1. 活动学习会话；
2. 失败或部分失败的后台 Job；
3. 未保存教材修订；
4. 待发布教材；
5. 待人工处理知识点。

恢复中心只聚合入口，不复制领域状态。

### 4.3 统一服务降级

公开环境会真实遇到 DeepSeek 限流、TTS 离线和 worker 繁忙。

页面不得只显示“服务正常/异常”，而应区分：

- 正常；
- 部分能力不可用；
- 繁忙，已排队；
- 需要重试；
- 维护中。

Cards Factory 生成不可用时，教材浏览和已有卡片学习仍应继续。

### 4.4 AI 与内容可信度

用户可见内容统一标记：

- 教材官方原文；
- AI 派生中文提示；
- DeepSeek 生成内容；
- 确定性分析；
- 用户已确认事实。

默认界面显示简洁标签，provider、model、hash 和时间进入详情。

### 4.5 帮助和问题反馈

不增加客服系统，但公开版本至少提供：

- 当前页面帮助；
- 数据和 AI 边界说明；
- 版本号和构建时间；
- 一键复制诊断编号；
- 问题反馈链接；
- 服务状态和已知问题入口。

不得把堆栈、本地绝对路径、环境变量名或原始数据库错误直接展示给访客。

### 4.6 法律和数据说明

UI 至少要说明：

- 教材原文和官方音频由用户合法提供；
- AI 结果可能出错，需要人工确认；
- 体验沙箱的保留期限；
- 上传内容、生成内容和音频缓存的用途；
- 哪些操作会调用外部 DeepSeek 服务。

这不是增加用户管理，而是公开服务的基本可信度。

## 5. 页面级目标结构

| 页面 | 当前主任务 | 公开 SaaS 目标 |
|---|---|---|
| Cards Factory | 生成卡片 | 文本/图片模式清楚、任务可恢复、额度透明、空状态可行动 |
| 今日学习 | 生成并进入队列 | 优先恢复旧会话，今日队列和跨日状态不冲突 |
| 学习计划 | 配置范围和负担 | 预览按学习方向统计，标签可搜索，变更影响清楚 |
| 复习会话 | 主动回忆和评分 | 本次进度/今日目标分离，专注模式，答案分层 |
| 学习记录 | 查看真实行为 | 空状态可行动，数据成熟后突出负担、困难和逾期 |
| 教材课程 | 校对、发布和学习 | 草稿走 Workflow，发布后以浏览学习为主 |
| 知识点 | 查询、裁决和加入学习 | 初始有入口，证据分层，未决工作可处理 |

## 6. 分阶段实施路线

### PS-G0：公开模式和基线

1. 确认“单工作区 + 公开体验沙箱”双模式；
2. 定义工作区身份、数据保留和高成本能力额度；
3. 建立 1280 与 1440 桌面截图基线；
4. 记录首次访问、跨天会话、刷新恢复和服务降级基线；
5. 禁止公开环境直接连接所有者真实 volume。

验收：

- 公开访问模式不会读写所有者真实数据；
- 页面始终显示当前工作区身份；
- 不增加账户、团队、角色和计费页面。

### PS-P0：状态正确性

1. 修复跨天活动会话恢复；
2. 分离本次队列进度和每日目标；
3. 修复教材确认/发布状态矛盾；
4. 为关键 view-model 增加矛盾检测；
5. 为上述状态增加 API、组件和 E2E 测试。

验收：

- 刷新、跨天和直接深链接不会隐藏活动工作；
- 同一对象不会同时显示互相矛盾的状态；
- 用户始终有明确的恢复或退出动作。

### PS-P1：公开 Shell

1. 增加 Workspace Badge；
2. Activity Center 改为服务端 Job 驱动；
3. 增加全局 Recovery Banner；
4. 增加降级、限流、维护和诊断反馈；
5. 统一 Page Header 和主动作规则。

验收：

- 后台任务跨刷新仍可见；
- 失败任务可以回到对应对象并重试；
- 高成本操作的排队或额度对用户透明。

### PS-P2：首次使用和空状态

1. 加入可跳过的五步产品内引导；
2. 重写四个产品域的首次空状态；
3. 提供合成示例和体验数据；
4. 增加清除体验数据和重新开始；
5. 确保引导不修改真实学习评分。

验收：

- 新访客在 30 秒内能找到第一个可执行动作；
- 每个空状态最多一个主动作；
- 演示数据与真实数据清楚区分。

### PS-P3：核心学习体验

1. 复习专注模式；
2. 本次进度与今日目标双层表达；
3. 长答案分层；
4. 音频操作去重和连续播放；
5. 学习结束摘要和下一步统一。

验收：

- 用户无需理解 FSRS 术语即可完成复习；
- 评分、音频和内容不会互相遮挡；
- 键盘可以完成揭示、播放、评分和结束。

### PS-P4：教材与知识点工作台

1. 教材发布后收起生产流程；
2. 教材列表键盘导航和播放状态；
3. 知识点最近查询和待处理首页；
4. 隐藏不可执行的容量和动作；
5. 统一 Evidence、Proposal 和 Confirmed Fact 的视觉。

验收：

- 已发布教材默认进入学习浏览；
- 未选择知识点时页面不出现三块无意义空白；
- AI 提案不会被误认为系统事实。

### PS-P5：设计系统和公开质量

1. 提取共享页面原语；
2. 统一中英文、状态和错误文案；
3. 增加 404、维护、离线和能力关闭页面；
4. 完成键盘、焦点、对比度和 200% 缩放检查；
5. 增加性能预算、错误监控和构建版本信息；
6. 收敛重复 CSS。

验收：

- WCAG 2.1 AA 关键路径检查通过；
- 1280 与 1440 桌面无溢出和遮挡；
- 页面不泄露绝对路径、堆栈、密钥和环境变量；

## 8. 成功标准

公开化成功不能只用“页面更现代”判断。至少满足：

1. 新访客无需阅读开发文档即可开始一次真实或沙箱学习流程；
2. 用户跨页、刷新、跨天后仍能找到未完成工作；
3. 所有关键状态、数量和进度可以追溯到权威数据；
4. 匿名访问不会读取或修改其他人的长期数据；
5. AI 和系统失败不会阻断已有内容的浏览和复习；
6. 核心流程通过桌面 E2E、视觉、键盘、降级和恢复测试；
7. 不增加用户管理，也不通过共享数据库假装解决用户隔离。

## 9. 当前建议

先执行 PS-G0 和 PS-P0，不先做新的视觉主题。

- 工作区隔离决定系统是否能安全公开；
- 状态正确性决定用户是否相信系统；

- 这些问题不解决，再漂亮的 UI 也只是可公开观看，不能成为可公开使用的 SaaS。

## 19. 2026-07-30 实施记录：统一确认对话框与焦点管理

本批解决的不是“弹窗看起来不一样”，而是同一种确认操作原来存在多套安全规则：

- 部分弹窗点击遮罩会直接关闭，部分不会；
- 部分弹窗支持 `Esc`，但关闭后焦点不会回到原操作；
- 部分弹窗没有焦点约束，按 `Tab` 可以进入被遮住的后台页面；
- 请求处理中仍可能关闭或重复提交；
- 学习计划的“修改”操作需要把焦点送到指定字段，通用焦点恢复曾与业务焦点跳转发生竞态。

这些差异会让陌生用户无法预测系统行为，也是公开 SaaS 场景下键盘可访问性和高成本操作安全的真实缺口。

### 19.1 共享弹窗契约

新增 `DialogSurface` 与 `ConfirmDialog` 两个共享原语：

1. 打开后焦点进入弹窗指定的首要控件；
2. `Tab` 与 `Shift+Tab` 被限制在弹窗内部；
3. `Esc` 在非处理中安全取消；
4. 关闭后焦点回到触发按钮；
5. 若业务主动把焦点送到其它字段，通用恢复不得抢回焦点；
6. 请求处理中设置 `aria-busy`，取消和确认按钮同时锁定；
7. 关键确认默认不允许点击遮罩关闭，避免误触；
8. 普通管理弹窗可以显式允许点击遮罩关闭；
9. 危险、警告和普通确认使用不同语义色，但共享相同键盘规则。

### 19.2 已迁移流程

以下流程已接入共享契约：

- 学习计划保存前的服务端范围复核；

- 提前结束复习会话；
- Knowledge Resolution 人工裁决；
- 将已调度知识点加入本次学习；
- Cards Factory 队列管理。

业务所有权保持不变：

- 学习计划仍由 Learning 服务保存和重建队列；

- 队列弹窗只操作生成任务，不接管 Activity Center。

### 19.3 保留独立实现的弹层

学习卡大弹窗已经拥有选区工具条、二级菜单、音频所有权和成熟的焦点陷阱。本批不把它强行迁入普通确认弹窗，避免破坏其复杂交互。

学习计划复核中的“修改”会关闭弹窗，并把焦点送到具体计划字段。首版共享实现关闭后又把焦点恢复到“检查并保存计划”按钮，覆盖了业务指定焦点。

- `Esc` 取消仍回到原按钮；

- 通用组件不会猜测业务下一步。

## 22. 2026-07-30 实施记录：高成本任务停止、继续与结果保留

本批统一公开服务中最容易造成误解的后台任务语义：用户点击“取消”不等于回滚已经完成的工作；失败或停止后继续也不应从头重复所有步骤。

### 22.1 Cards Factory 生成任务

卡片生成沿用现有持久化队列：

- 排队中的任务可以安全取消；
- 已运行的生成任务暂不提供强制中断，界面明确说明生成完成后结果仍会保存；
- 失败任务继续使用“重试失败任务”，成功后可直接打开生成的学习卡；
- 成功结果保留在卡片库和历史记录中，不因关闭队列弹窗丢失；
- 取消、失败、成功和最近结果继续由 Activity Center 提供跨页面恢复入口。

不对运行中的生成任务发送不可靠的强制终止信号，避免出现 Markdown 已写入但数据库、TTS 或审计状态没有完成的半成品。

### 22.2 教材后台 operation

教材 operation 现在支持协作式停止：

1. 排队状态取消后立即进入 `cancelled`；
2. 运行状态先持久化停止请求，再通过 `AbortSignal` 停止当前可中断的 TTS 步骤；
3. 已经成功的发布、物化或同步步骤保持 `succeeded`；
4. 取消后的 operation 可选择“继续未完成步骤”；
5. 重试只把未完成步骤重置为排队，不重复已经成功的步骤；
6. 服务重启时发现已持久化的停止请求，会收敛为 `cancelled`，而不是静默重新执行。

教材批量 TTS 与选区即时朗读继续共用 TTS 协调器。取消信号只终止当前教材批处理，不修改已保存教材原文、人工确认状态、学习计划或学习评分。

### 22.3 共享 UI 契约

`AsyncOperationPanel` 和领域适配器统一显示：

- 当前任务是否可以停止；
- 失败或取消后是否可以重试；
- 已完成结果是否保留；
- 下一步是“重试失败步骤”还是“继续未完成步骤”；
- 取消正在生效时，不把任务误报为已完成。

任务停止后仍保留 append-only operation event，Activity Center 只读取并导航，不替代领域服务写状态。

- 改变 FSRS、学习计划或知识点裁决；

## 33. 2026-07-30 实施记录：路由资源拆分与体积门禁

### 33.1 问题诊断

此前 `app/root.tsx` 无条件导入所有业务样式。用户打开任意页面时，都会同时下载 Cards Factory、学习、教材、知识点、工作流和 CardModal 的 CSS。

上一次 production build 的结果：

- 全局 root CSS：146.08 kB，gzip 22.37 kB；
- CardModal JS：159.57 kB，gzip 52.58 kB；
- Cards Factory 和复习会话都会把完整 CardModal 当成初始依赖。

这不会立即造成页面错误，但会让公开服务随着功能增加持续变慢。

### 33.2 实施方式

- `app/root.tsx` 只保留设计 token、页面标题、对话框和通用页面状态样式；
- Factory、Learning、Textbooks、Knowledge 和 Workflow 样式由对应路由加载；

## 35. 2026-07-30 实施记录：匿名公开沙箱

### 35.1 发生了什么

公开体验不再把多个浏览器放进同一个 viewer 或共享 SQLite。
`sandbox-gateway.mjs` 为每个匿名浏览器签发短期 HttpOnly 签名 cookie，并创建：

- 一个独立 viewer 子进程；
- 一个只属于该会话的 SQLite；
- 独立卡片、教材工作目录和选区 TTS 缓存；
- 3 张不含用户内容的合成示例卡和 23 个合成学习单元。

网关只保存 opaque session id，不建立账户、用户表或登录流程。

### 35.2 UI 行为

Product Shell 在所有页面持续显示：

- 当前为“体验沙箱”而不是个人工作区；
- 可读写或只读状态；
- 剩余清理时间；
- 高成本能力关闭时，明确显示“生成、图片识别和即时朗读未开放”；
- 高成本能力开启时，显示生成、OCR、TTS 的剩余额度；
- “重置体验数据”入口和明确的二次确认。

重置说明写明只清理当前沙箱，不影响个人工作区或其他访客。容量已满或实例启动失败时，
网关显示独立错误页，不会静默连接到所有者数据。

公开沙箱关闭知识图谱能力时，内部知识同步任务不得进入用户活动中心。合成学习单元虽然
可以在后台初始化，但 Shell 不显示与用户无关的红色活动数字。

### 35.3 安全与成本边界

- `docker-compose.public.yml` 不挂载所有者 volume；
- cookie 使用 HMAC-SHA256 签名、HttpOnly、SameSite=Lax，HTTPS 环境必须 Secure；
- 一个存储根只允许一个网关持有独占锁；
- 网关启动会清理上一次异常退出留下的 orphan 沙箱；
- 到期、重置和正常关闭都会终止子进程并删除短期目录；
- 生成、OCR、TTS 和存储额度按会话持久化；
- 高成本能力默认关闭，打开后额度用完统一返回 429；
- KG planning、LLM enrichment 和增量同步在公开沙箱默认关闭。

### 35.4 可重复隔离验收

`npm run test:public-sandbox` 会启动真实网关和两个真实 viewer 子进程，验证：

5. A 重置后换新 id、恢复示例与额度，B 完全不变；
6. 网关退出后所有沙箱目录和独占锁清理完成。

真实桌面浏览器也已验证：Shell 可见沙箱模式、期限、能力状态、重置确认；
